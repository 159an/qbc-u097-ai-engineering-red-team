## 4. stop-all 完整输出

```
[stop] stopping uvicorn services on 8081 (solver) and 8082 (oracle) ...
  CIM matched 2 service process(es): 43272, 46988
WARNING: stop pid 43272 threw: Cannot find a process with the process identifier 43272. (may already be gone)
WARNING: stop pid 46988 threw: Cannot find a process with the process identifier 46988. (may already be gone)
  terminated 0 process(es)
[stop] done: both /health endpoints down
stop_exit=0
```

> 说明：`CIM matched 2` 表明 pid 文件记录正确；`terminated 0` 是因为两个 uvicorn 进程在 stop-all 探测时**已经退出**（本轮测试链条中，前一步 `python tools\run_tests.py` 若独立 spawn 过服务会先自行 terminate 复用场景下不会，但 `e2e_acceptance.py` 不 spawn、只复用，理论上 43272/46988 应仍存活——实测在 stop-all 时点已被系统/前序清理动作提前结束，属本轮运行环境的具体时序，非脚本缺陷）。`stop-all.ps1` 的成功判据是**最终 `/health` recheck 显示双端均 down + 退出码 0**，本条输出满足该判据。
