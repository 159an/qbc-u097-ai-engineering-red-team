## 一、作品定义（一句话）

**让一个基于 Agnes Harness（AGH）的智能体，在不被告知任何数值分析理论的前提下，自主设计实验、调用求解器与独立解析解基准、二分收敛最小反例，从而发现一个工程传热求解服务的失效边界，并给出可复现证据。**

不是"我们写了个求解器"，也不是"我们写了个测试工具"——**作品是那个能自主完成工程验证任务的智能体**；求解服务只是它的实验对象。这句话在答辩时要原样说出来。

## 二、为什么目标系统选"数值求解器"而不是电商

原始方案用虚拟电商，红队内核很好，但有一个**会被评委追问的硬伤**，以及一个**技术上的自相矛盾**：

| 问题 | 说明 |
| --- | --- |
| 主题契合 | 赛事主题是"AI+**科学与工程**"，四类方向为科研求解与验证 / 工程仿真与优化 / 智能制造与系统 / 设计与交叉应用。电商是业务系统，不是科学或工程对象 |
| 自导自演 | "我们注入一个 bug，再让 AI 找出来"——评委会问：*你自己塞的 bug 自己找，价值在哪？* |
| 判分困难 | 电商的"库存 -2"是布尔结论，但"业务不变量"要自己定义，容易变成主观约定 |

换成数值求解器后，这三点**同时被解决**：

| 优势 | 说明 |
| --- | --- |
| 天然属于工程仿真 | 传热/扩散方程是 CFD、结构动力学、传热学的基础，无争议 |
| **不需要注入任何人为 bug** | Agent 发现的是**数值方法固有的数学失效边界**，是教科书级定理的独立再发现，无法被质疑"自导自演" |
| **结果正确性可数学判定** | 临界值是实数（可二分收敛到任意精度）、收敛阶是整数（2 阶）、振荡阈值是可算的（网格 Péclet 数 = 2）——**不是主观约定，是数学事实** |
| 最小反例天然成立 | "最小反例自动收敛"在电商里要自己造；在这里就是**二分搜索找临界参数**，优雅且可验证 |
| 演示好看 | 误差-参数曲线在临界点翻转，5 分钟视频有明确高潮 |

> **关键纪律：不做人为注入的隐藏 bug 作为主线。** 服务提供*声明式*的故障开关，**只用于满足赛事「失败类测试」的必填要求**，且 Agent 的工具集里看不到这些开关。主线始终是"发现固有边界"。

               │ · FTCS / BTCS / CN │   │ · 闭式解析解（级数）   │

               └────────────────────┘   └──────────────────────┘

**接口必须冻结在第一天**（见第五节 API 契约），因为这是两人唯一的耦合点。冻结后 A 可以在服务只返回假数据的情况下先开发工具，B 可以不管 Agent 侧。

### 三条不可违反的红线

1. **被测系统与验证基准必须结构独立**：`/solve` 是数值离散解，`oracle` 是解析级数解，**两个进程、两套算法**。若基准与被测同源，验证就是自证——这一条是"验证严谨性"的核心，必须写进报告。
2. **判定不能交给模型**：实测证据在 `evidence/conformance/FINDING-1`——让模型算 12 行 CSV 的两列均值，它两个都算错了（21.4917 / 101.3083，基准 21.6667 / 101.3417），而同一回合 AGH 内建校验器仍判 `pass`。所以**误差计算、临界值二分、收敛阶拟合全部由代码完成**，模型只负责设计实验、选策略、解释根因。
3. **模型调用仅限 Agnes**：只用 `agnes-3.0-flash`（当前凭据只解锁这一个）。不得接入任何其他厂商模型。求解服务与 Oracle 是确定性代码，**不含任何 LLM 调用**。
4. **基准事实必须对 Agent 不可达**：`ground-truth/` 若放在 Agent 的工作区内，Agent 可以用内置 `read` 工具直接读到标准答案，整个"自主发现"就不成立了。对策：
   - Agent 的工作区设为 `runtime/agent-workspace/`（一个**不含** `ground-truth/` 的目录），目标系统只通过 HTTP 暴露，Agent 不需要读任何项目文件
   - **开工前必须实测**：发一条探针任务让 Agent 去读 `ground-truth/ground-truth.json`，**必须确认它读不到**。Windows 上 `sandbox.l1=unavailable`（实测于 `doctor platform`），文件边界不完全可靠，所以这条不能靠假设

## 五、接口契约（第一天冻结，之后改动需双方同意）

### 5.1 求解服务 `:8081`

**`GET /health`**
```json
{ "ok": true, "schemes": ["ftcs","btcs","cn"], "version": "1.0.0" }
```

**`POST /solve`** — 提交一次数值求解
```json
{
  "scheme": "ftcs",
  "alpha": 1.0,
  "nodes": 101,
  "dt": 0.0001,
  "tEnd": 0.05,
  "length": 1.0,
  "initial":  { "kind": "sin", "amplitude": 1.0, "modes": 1 },
  "boundary": {
    "left":  { "kind": "dirichlet", "value": 0.0 },
    "right": { "kind": "dirichlet", "value": 0.0 }
  },
  "advection": { "enabled": false, "velocity": 0.0 },
  "probes": [0.25, 0.5, 0.75],
  "recordEvery": 10
}
```
响应（成功）
```json
{
  "taskId": "t-8f3a...",
  "status": "completed",
  "numerics": { "dx": 0.01, "dt": 0.0001, "r": 1.0, "peclet": 0.0, "steps": 500 },
  "probes": [{ "x": 0.5, "points": [{ "t": 0.0, "u": 1.0 }, { "t": 0.001, "u": 0.9876 }] }],
  "summary": { "maxAbsU": 1.0, "minU": 0.0, "maxU": 1.0, "blowUp": false }
}
```
约定：
- `r = alpha * dt / dx²`、`peclet = velocity * dx / alpha`，**由服务计算并返回**（不让模型算）
- `blowUp`：出现 NaN/Inf 或 |u| 超过初始幅值 1e6 倍时为 `true`
- 参数非法（`alpha <= 0`、`nodes < 2`、`tEnd < 0`）返回 **400**，body 含 `{"error":{"code":"...","message":"..."}}`
- 探针位置按归一位移 `x/length` 解释

### 5.2 Oracle 服务 `:8082`（独立进程）

**`POST /exact`** — 闭式解析解
```json
{
  "alpha": 1.0, "length": 1.0,
  "initial": { "kind": "sin", "amplitude": 1.0, "modes": 1 },
  "boundary": { "left": {"kind":"dirichlet","value":0.0}, "right": {"kind":"dirichlet","value":0.0} },
  "points": [{ "x": 0.5, "t": 0.001 }, { "x": 0.25, "t": 0.02 }]
}
```
响应
```json
{ "method": "separation-of-variables-series", "terms": 200,
  "points": [{ "x": 0.5, "t": 0.001, "u": 0.996805 }] }
```
约定：
- **必须用与被测求解器完全不同的代码路径**（解析级数展开，不是数值离散）
- 当所给初值/边界**没有闭式解**时，必须返回 **422** 并说明原因，**不得用数值解冒充解析解**——这条是红线，谎报基准比没有基准更糟
- 级数项数 `terms` 需在响应中声明，并验证截断误差 < 1e-10

### 5.3 故障开关（不给 Agent 看）

通过**环境变量 + 进程重启**控制，**不暴露 HTTP 控制端点**，Agent 的工具集里也没有相关工具。用于跑赛事的「失败类测试」。

| 环境变量 | 效果 | 应被哪类攻击发现 |
| --- | --- | --- |
| `QBC_FAULT_CFL_GUARD=off` | 关闭稳定性保护，允许 `r > 0.5` 静默进入不稳定区 | 正确性攻击（与 oracle 偏差爆炸） |
| `QBC_FAULT_SHARED_STATE=on` | 求解器复用进程级共享数组，不按请求隔离 | 压力攻击（并发结果互相污染） |
| `QBC_FAULT_SILENT_CLAMP=on` | 非法参数（负 `alpha`）不报 400，静默取绝对值 | 边界攻击（200 但结果错） |
| `QBC_FAULT_PARTIAL_ON_TIMEOUT=on` | 超时返回部分结果但不标记 `incomplete` | 故障攻击 |
