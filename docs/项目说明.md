### 3. 参考方向（2–3 个最贴切）

1. **科学计算与仿真**：被测对象是工程传热偏微分方程（热扩散 + 中心差分对流）的数值求解服务。
2. **数学计算与科研智能体**：核心问题是「如何用数学可判定的基准去裁决一个数值结论是否可信」，而非纯工程实现。
3. **科研 Agent 与 Harness 工程**：全流程以 Agnes Harness 作为执行底座，由智能体自主规划、调用工具、观察反馈、验证结论，而非人工写死脚本。

### 4. 项目摘要（150–250 字）

被测系统是一个**纯确定性**传热求解服务（FTCS/BTCS/CN 三种时间推进格式、Dirichlet/Neumann 边界、中心差分对流项，HTTP 端口 8081），其验证基准是一个与之**结构独立**的解析解 Oracle（基于分离变量法级数与稳态对流扩散指数解，纯 math 级数实现，HTTP 端口 8082）。两服务代码路径、算法路线、进程完全隔离；无闭式解时 Oracle 明确返回 **422（E_NO_CLOSED_FORM）而非冒充数值解**，守住「基准不得谎报」的红线。围绕两者，实测四个数学性质基准 **P1 稳定性临界、P2 收敛阶、P3 对流振荡阈值、P4 能量守恒判据**全部达标；端到端自检 14/14 通过，全量回归测试 22 项全部通过。

### 5. 问题来源与目标

AI 产出的「数值结论」常常无法被直接信任——它可能给出貌似合理但超出稳定域、或偏离收敛阶预期的数值，而使用者缺乏低成本、可自动化的复核手段。本项目把「判定 AI 数值结论是否可信」这一原本依赖人工经验判断的环节，**下沉为确定性代码 + 结构独立解析基准**：任何 AI 给出的数值结果，都可以被送入本仓库的靶场，与解析解/离散精确解对照，机器即可给出可信与否的量化裁决。目标是让 AI 数值结论**可被机器复核**，而非依赖作者自检。

### 6. 核心方法

- **解析解/离散精确解对照**：数值解（离散格式）与结构独立的解析 Oracle（级数/指数闭式解）逐点对比，偏差即定量判据。
- **四性质基准测量**：
  - **P1 稳定性临界**：测得 FTCS 格式稳定域上限 $r^* \approx 0.5$（实测 0.500903，理论 0.5，偏差 9.03e-4，已如实记录该有限观测时间带来的固有偏差）。
  - **P2 收敛阶**：实测收敛阶 2.0（errorRatio 4.0023），与二阶理论值一致。
  - **P3 对流振荡阈值**：实测网格 Peclet 数阈值 2.0，与「中心差分无振荡」理论临界 $Pe_{cell}=2$ 一致。
  - **P4 能量守恒判据**：Neumann/绝热边界下总热量漂移 $H_{fvm}$ 实测为 **0.0**（对照用朴素均匀权重 $H_{uniform}$ 漂移 9.074e-3，仅作方法对照、不计入判据）。
- **全量回归测试**：任何修复/改动后必须重跑全量测试，防止回归。

### 7. Agnes Harness（AGH）执行流程（重点）

AGH 在本项目中承担**核心任务编排**，而非仅仅是「跑一下命令」。一次完整的靶场验证循环包含如下**连续步骤**：

1. **任务规划**：AGH 读取求解服务接口契约与物理假设，生成攻击/验证计划（哪些参数边界、哪个故障开关、要验证哪条红线），形成可执行的实验列表。
2. **能力调用**：按计划在会话内连续调用——
   - `shell`：启动/停止两个 HTTP 服务（`scripts/start-all.ps1` / `stop-all.ps1`）；
   - `read` / `write` / `edit`：修改被测代码或故障开关、记录观测值；
   - `grep`：在代码中定位可疑实现（如 CFL 守卫缺失、边界处理是否用了朴素幽灵点法）；
   - **经 HTTP 调用 8081（solver）与 8082（oracle）两个服务**：`/health` 探针、`/solve` 数值解、`/exact` 解析基准，形成「数值 vs 基准」的逐点差异数据。
3. **执行反馈**：每次调用返回的状态码、数值序列、耗时、`numerics`/`summary` 字段被 AGH 作为下一轮决策的输入，而非一次性脚本跑完收工。
4. **异常定位与纠错**：某次 `/solve` 结果与 Oracle 偏差超出理论收敛阶预期、或 `/health` 探针异常时，AGH 用 `grep`/`read` 定位到具体机制（如边界处理写法错误、`blowUp` 状态被谎报），再做最小改动复测。
5. **结果验证**：所有修复必须重跑全量回归测试与四性质基准测量，确认无回归、且判据数值落在理论区间，才能进入下一步。
6. **git 提交与推送**：验证通过后，AGH 执行版本提交与推送，保留完整可追溯的证据链（`evidence/` 下机器可读 JSON + 人类可读 Markdown 报告各一份）。

**明确声明：两个服务（solver / oracle）内部零 LLM 调用，全部为纯确定性数值代码；AGH 只负责编排与执行，不改变任何一处数值判定结果本身。** 换句话说，AI 是「做实验的人」，靶场是「客观的尺子」，尺子本身不含 AI。

### 11. 异常处理样例（现象 → 根因 → 修复 → 复测）

**样例 a）`stop-all.ps1` 报 `Stop-ServicePids : CommandNotFoundException`**
- 现象：一键停止脚本调用共享库中的 `Stop-ServicePids` 函数时报命令不存在，停止流程中断。
- 根因：`scripts/lib-qbc-services.ps1` 中该函数在多次功能合并中遗留缺失（合并时未完整保留）。
- 修复：在 `scripts/lib-qbc-services.ps1` 中补回 `Stop-ServicePids` 函数实现。
- 复测：再次运行 `stop-all.ps1`，输出 `CIM matched 2 → terminated 2 → both /health down`，`exit=0`，两个端口均确认关闭。

**样例 b）`start-all.ps1` 报 `VariableNotWritable`**
- 现象：一键启动脚本在写入某变量时报「变量不可写」，启动流程中断。
- 根因：脚本中形参名为 `$Pid`，与 PowerShell 只读自动变量 `$PID` 同名，赋值被拒绝。
- 修复：将形参改名为 `$procId`。
- 复测：再次运行 `start-all.ps1`，输出 `solver/oracle ready=True`，两个服务均正常就绪。

**样例 c）P4 判据计算错误：均匀权重得 9.07e-3，而应得 0.0**
- 现象：按朴素均匀权重（$\sum u_i \Delta x$）计算的总热量漂移为 9.07e-3，与「绝热边界下总热量应严格守恒」的理论预期（漂移 0）不符，判据 P4 假性失败。
- 根因：均匀权重公式在 Neumann（绝热）边界处**没有做端点半权处理**，端点贡献被错误地全权计入，引入系统性偏差；随后进一步排查发现 Neumann 端点用的是**一阶单侧**边界条件，本身精度不足。
- 修复：① 改用端点**半权**的有限体积量 $H_{fvm}$ 作为判据，得漂移 **0.0**；② 将 Neumann 端点边界条件从一阶单侧改为**二阶镜像幽灵点**，三个格式（FTCS/BTCS/CN）的 $H_{fvm}$ 漂移分别降到 **0.0 / 4.7e-12 / 2.8e-12**，达到机器精度水平。
- 复测：全量回归测试与 P4 基准测量重跑通过，四性质判据数值与 `ground-truth/ground-truth.json` 记录一致。

### 12. 边界与失败样例（供材料 #6 使用）

**边界样例（全部通过、不崩溃）：**
- `nodes=2` 与 `nodes=3`：极小网格请求不崩溃，返回结构完整的响应；
- `nodes=1`：请求 `nodes=1` 被参数校验拦截（400），不产生无意义求解；
- `tEnd=0`：零时长请求返回空时间序列，不崩溃；
- `tEnd=200`：超长时长请求在 `maxSteps` 限制内正常完成或被 `maxSteps` 守卫拦截；
- `r=0.51`：超出 FTCS 稳定域，被 **CFL 守卫**明确拦截（而非静默跑出发散结果后谎报稳定）；
- `/exact`（Oracle）：请求无闭式解的边界条件组合（如 Neumann + pulse 初值），返回 **422（E_NO_CLOSED_FORM）**，而非冒充数值解。

**失败样例（对应 #11 中样例 a/b，复现与修复记录已完整留档）：**
