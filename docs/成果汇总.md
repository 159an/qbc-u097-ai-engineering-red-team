## 一、作品定义

> **一个基于 Agnes Harness（AGH）的智能体，在不被告知任何数值分析理论的前提下，自主设计实验、调用求解器与独立解析解基准、二分收敛最小反例，从而发现一个工程传热求解服务的失效边界，并给出可复现证据。**

作品本体是**那个智能体**。传热求解服务是它的实验对象（靶场），不是作品本身。

   └──────────────────────┘   └─────────────────────────┘

### 三条红线（设计约束，有实测依据）

1. **被测系统与验证基准必须结构独立**：两个进程、两套算法（数值离散 vs 闭式解析）。若"标准答案"与"被检查的答案"同源，验证即自证。
2. **判定不得交给模型**：误差、临界值、收敛阶、热量漂移全部由代码计算。依据见下方「我们的发现 1」。
3. **基准事实必须对智能体不可达**：智能体工作区为 `runtime/` 下的独立目录，**不含** `ground-truth/`。

**执行统计（D1）**：37 次工具调用、25 个连续步骤、32 次推理调用、690 个事件，全部使用 `agnes-3.0-flash`，断言 7/7 通过。

#### D1 中值得单列的两点

**其一：智能体自己发明的判据比服务自带的更敏锐。**
它预先固定判据为「不稳定 ⟺ `summary.maxAbsU ≥ 1.0`」，依据是**离散极值原理**（脉冲初值峰值恰为 1.0，稳定区场只能衰减、不可超越初值峰值）。随后它发现服务自带的 `blowUp` 字段"远比我这个阈值钝"：在 r=0.5001357 时真实已越界，`blowUp` 仍是 `false`（要到 r≈0.5002、maxAbsU≈2.7×10⁷ 才翻 `true`），因此**拒绝依赖该字段**。

**其二：它独立推导出偏差的物理来源。**
它没有把 0.5001356 与 0.5 的差异当成误差，而是给出可验算的解释：离散最高模的中性点是 `r = 0.5/sin²(99π/200) ≈ 0.500125`（有限网格修正），再叠加"需把最高模放大约 50 倍才判为失稳"（有限阈值），翻转点被推到 0.5001356。**这与我们此前在设计阶段发现该问题时的推理路径完全一致。**

#### D3 中值得单列的一点

智能体没有停留在"字段与现象不符"，而是**追加扫描**去刻画该字段何时说谎，并给出处置建议：

> 「该字段似乎仅在有限步数窗口内、按某种内部参数预判置 true……一旦数值以渐进方式上溢/溢出统计即回落到 false——**它不可作为稳定性判据使用，应一律以"总热量守恒校验 + probe 幅值/奇偶振荡"为独立判据。**」

## 五、我们在过程中发现并修正的缺陷

**这些是真实的踩坑记录，不是包装。** 每一条都由实测暴露，并且都影响了设计。

### 5.1 作品层面的发现

| 编号 | 发现 | 影响与处置 |
| --- | --- | --- |
| **F1** | **模型 token 级算术不可靠，且内建校验器察觉不到**：让模型算 12 行 CSV 的两列均值，两个都算错（21.4917 / 101.3083，基准 21.6667 / 101.3417），而同回合 AGH 的 `verifier/signal` 仍判 `pass` | 确立红线 2：**判定全部下沉为代码**。靶场与工具直接返回 `r`、`peclet`、`overshoot`、热量漂移等可判定量 |
| **F2** | **初值只支持 sin 会让 P1 在数学上测不出来**：`r>0.5` 的失稳是最高网格模态的性质，而单模态 sin 的放大因子 `G = 1 − 4r·sin²(π/(2(N−1)))`，N=101 时 r 要到约 **2024** 才失稳 | 契约新增 `pulse` 初值（且用矩形脉冲而非随机数，保证可复现）。智能体后来**独立复现了这条推理** |
| **F3** | **Neumann 边界用朴素幽灵点法不严格守恒**：推导 Σ 变化量得 `−r(u₀−u₁+u_{N−1}−u_{N−2})`，一般不为零，总热量会漂移 | 改为**通量形式**（系数是 r 而非 2r），P4 实测漂移为 0 |
| **F4** | **工具 schema 比目标更严会屏蔽目标行为**：`alpha` 声明 `exclusiveMinimum:0`、`probes` 声明 `[0,1]`，导致非法输入在本地就被拒，智能体看不到服务自己的 400 响应，边界任务被迫 `blocked` | 放宽业务域约束，**业务域一律交目标裁决**。原 `blocked` 已作为"如实报告能力缺口"的正面证据保留 |
| **F5** | **`requiresApproval:'never'` 不足以让非只读工具免审批**：AGH 的判定是 `needsAsk = … \|\| (taint && !isReadOnly)`，会话被 taint 后非只读工具必须审批，非交互环境无人应答即被拒 | 靶场求解接口是**纯函数**，如实改声明为 `isReadOnly:true / replay:'safe'`。并在注释中写明：若靶场将来有真实副作用必须改回 |

### 5.3 智能体自身的失误（同样如实记录）

| 编号 | 现象 | 处置 |
| --- | --- | --- |
| **F11** | **智能体在 P3 任务中捏造了一个不存在的服务缺陷**。它的实验部分全对（二分锁定 Pe=2、推导出中心差分系数不等式、网格加密对照正确），但在汇总表格里**把 peclet 值与速度配错了行**（把 v=100→1 记成 v=1→1、把 v=0.01→0.0001 记成 v=0.5→0.0001），并在此之上断言「`numerics.peclet` 字段在低速度区存在明显的数据不稳定/随机化」 | 已用 `tools/verify-agent-claims.mjs` **机械否证**：只用它自己收到的 41 条返回，检验不变量 `overshoot > 0 ⟺ peclet > 2`，**0 条违反**（peclet 覆盖 0.0001~100）。另经直接 HTTP 核验，v=1/10/100/200/201/500 时服务返回的 peclet 与 `v·dx/α` 精确一致 |

**这条发现的价值大于它本身的错误。** 它正是本作品核心主张的现场证据：

> **模型的叙述不是事实来源，轨迹才是。**

因此本仓库的证据流水线 `tools/analyze-trajectory.mjs` 从 **AGH 原生事件流**生成断言，
而不是采信模型的自然语言总结。**连"模型说错了"这件事，也由代码而非人工判断来证明**——
这正是 `tools/verify-agent-claims.mjs` 存在的理由。

这也是对 §5.1-F1（模型算错均值而校验器仍判 pass）的补充：模型的不可靠不仅出现在**算术**上，
也出现在**对自身实验结果的转述**上。两者都指向同一个工程结论：**验证必须锚定在可核查的记录上。**

### 5.2 AGH 底座层面的发现（可复用于其他团队）

| 编号 | 发现 | 证据 |
| --- | --- | --- |
| **F6** | **非交互环境下 `shell` 命令被审批拒绝**，连只读的字节统计也拒；AGH 内置 `web_fetch` 明确 *"Anonymous GET only"* 且 *"no private network"*，够不到本地服务 | `evidence/conformance/B2`、`F2` |

## 六、已知局限（如实声明）

1. **只实现了 FTCS**。`/health` 里列出 `btcs` / `cn`，但 `/solve` 对它们返回 `400 E_SCHEME_NOT_IMPLEMENTED`。**这是刻意的**：宁可如实说不支持，也不假装实现（假装实现会被智能体发现算得不对，反而打穿自己的作品）。
2. **P3/P4 的自主发现任务尚未跑**（靶场性质本身已由独立基准验证）。D1/D2/D3 已完成。
3. **并发一致性攻击尚未跑**（`shared-state` 故障开关已实现）。
4. **Windows 沙箱层不可用**：`doctor platform` 实测 `sandbox.l1=unavailable`、`sandbox.network=unavailable`，因此文件与网络的执行边界不完全依赖沙箱，而由能力限制代码兜底（工具限定本地主机）。
5. **基准独立性是"算法级"而非"组织级"**：求解器与 Oracle 由同一成员实现，但走**完全不同的算法路径**（数值离散 vs 闭式解析），且分属两个进程。这是结构上的独立，但不等同于独立的第三方复现。
6. **P1 的基准测量存在已知偏差**（0.500903 vs 理论 0.5，约 9e-4），成因是"有限观测时间内幅值需增长 10 倍才判发散"。智能体的判据更锐利，反而更准——这在 §3.3 已如实记录。
